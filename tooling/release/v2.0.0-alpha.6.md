# Qiongli v2.0.0-alpha.6 CLI Registry Candidate

Status: **Preparing CLI GitHub Release** under ADR 0219. The maintainer superseded
the App/Community Alpha release prerequisite on September 9. The historical
registry and signed-lifecycle gaps below do not block direct CLI GitHub downloads;
they still limit managed activation/update and registry publication claims.

The current release owner is `./scripts/release_ready.sh --cli-github --version
v2.0.0-alpha.6 --staging-dir <new-external-dir>`. Publish only its `assets/`
directory, with user-facing installation/limitation notes, at the receipt's exact
source tag. Verify all public asset hashes and installation after publication.
No App, Community Alpha promotion, signing private key or registry login is
required for this GitHub-only release. npm/wheel attachments are local-install
packages, not uploads to npm or PyPI. Cargo registry publication remains pending.

This candidate preserves native CLI project/Capture/Graph queries, retrieval,
Zotero, recovery and Lite/Full MCP. The first binary distribution target is
macOS Apple Silicon. Cargo installs from source; npm and PyPI carry the same
native executable. App replacement and full 1.19 cutover are separate gates.
Windows installation remains partially complete/paused.

## Local packaging

Build with `cargo build --manifest-path packages/qiongli-native/Cargo.toml -p
qiongli --bin qiongli --no-default-features --locked --offline --release`.
Then run from the checkout, choosing new external directories:

```sh
python3 scripts/native_registry_packages.py \
  --out-dir /tmp/qiongli-alpha6-packages \
  --binary "$PWD/packages/qiongli-native/target/release/qiongli" --package-cargo
python3 scripts/native_registry_install_check.py \
  --packages /tmp/qiongli-alpha6-packages --out-dir /tmp/qiongli-alpha6-install \
  --cargo-archives
```

The generator stages all nine Rust crates with exact internal versions and
in-crate content/Zotero assets. The existing content lock still verifies every
build. It leaves the canonical workspace non-publishing and the frozen 1.x
npm/Python packages unchanged. The staged Cargo manifest is the publish input. `--cargo-archives` extracts
the checksum-checked archives, patches only the eight internal dependencies to
those extracted paths, and installs with `--locked --offline`; external dependency
versions and checksums stay locked. Cache dependencies with `cargo fetch --locked
--manifest-path packages/qiongli-native/Cargo.toml --target aarch64-apple-darwin`
first if needed. `--cargo-target-dir` can reuse an existing build cache.
Cargo archives are assembled with `--no-verify`; that flag supplies no validation
claim. The receipt lists exact checksums, and the install checker validates the
npm/PyPI bytes before installation in a disposable prefix/venv.

The native npm launcher inherits stdio and propagates process termination; the
Python entrypoint replaces itself with the same native binary. Both expose
`qiongli` and `ql`, have no install-time download, and retain all product
approval/CAS checks. Wheel tags derive from the executable's macOS deployment
floor. Other binary targets require their own packaging and runtime evidence.

- Download and install from each public registry after publication. Announcement
  is a separate decision. No public install command is advertised as working yet.

Use the selected package manager for upgrades/removal. Preserve research data
