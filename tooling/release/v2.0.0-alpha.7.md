# Qiongli v2.0.0-alpha.7 — Three-platform CLI

This candidate adds native CLI installation packages for macOS Apple Silicon,
Windows x64 and Linux x64 (glibc 2.35+). No Qiongli App is required.

The canonical version is `2.0.0-alpha.7` (SemVer), Git tag
`v2.0.0-alpha.7`, PyPI version `2.0.0a7`, and npm distribution tag `next`.
Beta versions map the same way: `2.0.0-beta.1` → `2.0.0b1` on PyPI.
Cargo registry publication is deferred. Alpha.6 assets are unchanged.

## Installation

After registry publication is verified:

```sh
npm install --global qiongli@next
qiongli --version
```

```sh
python -m pip install --pre qiongli==2.0.0a7
qiongli --version
```

Use a Python virtual environment or pipx if the system Python is externally
managed. Both channels expose `qiongli` and `ql`. npm requires Node 18+; the wheel
requires Python 3.9+. Neither wrapper downloads executables during installation.
PyPI selects the native wheel; npm selects the bundled executable for the host.
The standalone GitHub archives need neither Node nor Python.

For MCP, configure the Host to run the absolute executable path with
`mcp serve --profile full --transport stdio` (or `--profile lite`). The Host owns
models and credentials. Existing research preview/approval/CAS checks remain.

## Qualification and limits

`native-cli-distribution.yml` builds and installs on all three native runners,
then assembles one npm package and three wheels and installs those combined
release bytes again on all three systems. Linux wheels pass auditwheel's
manylinux_2_35 check. The existing npm/PyPI workflow filenames and environments
publish only after the GitHub Release is published, checking its source, assets
and successful exact-source distribution CI first. npm uses `next`.

This candidate is not qualified until that matrix passes. Registry availability
is a separate result, verified after upload; install commands above do not claim
an upload has already occurred. Intel macOS, Linux ARM, Windows ARM-native and
other architectures are not advertised. Managed Plugin/Skill activation,
automatic migration and signed self-update retain their existing authority
requirements. Full 1.x replacement and complete research baseline acceptance
remain open; direct CLI installation does not grant managed-product authority.

Use a package manager or a new extracted directory for upgrades. Preserve research
data/backups and the previous executable for rollback; selecting an older binary
does not reverse data migrations. Tags and published assets are immutable.
