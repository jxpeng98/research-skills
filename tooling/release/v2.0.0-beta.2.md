# Qiongli v2.0.0-beta.2

Beta.2 helps you find older Qiongli commands and review a migration before
changing your setup. GitHub downloads, npm, PyPI and Cargo share this native CLI.

## Installation review

- `qiongli install inventory --paths exact` lists commands found on PATH and in
  known user installation locations. It groups package aliases, identifies npm,
  Python and Cargo metadata, and marks the running executable. Other environments
  and shell aliases may need separate inspection; unknown binaries are never run.
- `qiongli doctor` includes a redacted CLI inventory and flags multiple entries.
- `qiongli install migrate --interactive` lets you choose a preferred installation
  and request archive or uninstall guidance for each remaining copy. Enter keeps
  the current setup. No files, PATH entries or Host settings are changed. Uninstall
  guidance leaves execution to the user and warns about shared command files.
- Running `qiongli` without arguments in a terminal opens the same review. Help,
  scripts and MCP remain noninteractive. npm can open it during a foreground
  installation; pip and Cargo users run it after installation.

Use the new executable's full path when an older command appears first on PATH.
Package metadata versions are labelled separately from the running CLI version.

## Install

Choose the complete archive for macOS ARM64, Windows x64 or Linux x64 from
**Assets**, verify `SHA256SUMS`, extract, and run `./qiongli --help` (Windows:
`.\qiongli.exe --help`). These archives need no separately installed Python,
Node.js, Rust or package manager. Linux requires glibc 2.35+.

Alternatively, use one package manager:

```sh
npm install -g qiongli@2.0.0-beta.2 --foreground-scripts
python -m pip install qiongli==2.0.0b2
cargo install qiongli --version 2.0.0-beta.2 --locked
```

npm needs Node 18+, PyPI needs Python 3.9+, and Cargo builds from source with
Rust 1.97+ and a native linker. npm's `next` tag follows prereleases. npm's review
runs only with terminal input/output; disabling install scripts still leaves a
working CLI. After pip or Cargo installation, run the installed executable with
`install migrate --interactive`.

## Publication and limits

Release Automation waits for the exact tag's three-platform builds and combined
install checks before publishing GitHub assets. It then dispatches the existing
npm, PyPI and Cargo workflows, which retain their verification and credential
gates. Registry availability depends on those separate jobs completing.

The release includes platform Plugin archives. External Marketplace catalog
updates remain separate. Models, research data, Plugin caches and Host settings
are outside the installation review. This release does not add automatic package
removal, archive moves, data migration or managed-product authority.

To roll back, select a retained executable or reinstall a pinned version using
its original package manager. Switching binaries does not reverse research-data
migrations. Published tags and release assets remain immutable.
