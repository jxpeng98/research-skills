# Qiongli v2.0.0-alpha.8 — Codex-first research workflows

This CLI-first prerelease brings the current research Skill library to the
native CLI. Codex is the primary Host; Claude Code and other Hosts use the same
research contracts and keep their configured models. No Qiongli App is required.

## Changes

- Bound research work to the requested answer or deliverable. Reuse evidence and
  loaded guidance, avoid automatic workflow expansion and repeated review loops,
  and preserve missing-evidence, permission and preview/approval/CAS boundaries.
- Improve routing between adjacent academic tasks, distinguish survey design
  from measurement method, and preserve unreported study details as unknown.
- Add previewed local Codex/Claude Plugin source export, update and removal.
  Exported sources retain exact receipts; Host registration remains a separate
  user action.
- Extend offline evaluation with source-bound reading-to-manuscript and direct
  paragraph cases. Structural checks do not establish prose fidelity or full
  research-baseline acceptance.
- Restore Codex/Claude `qiongli-next` marketplace distribution from the same
  native resource pack as npm. Shared Skill files retain their exact bytes;
  the public Plugin pins this npm version for Lite MCP instead of drifting to
  a legacy Python runtime or a moving npm tag.

## Installation

The canonical version is `2.0.0-alpha.8`, Git tag `v2.0.0-alpha.8`, npm channel
`next`, and PyPI version `2.0.0a8`.

```sh
npm install --global qiongli@2.0.0-alpha.8
qiongli --version
```

```sh
python -m pip install --pre qiongli==2.0.0a8
qiongli --version
```

Use a virtual environment or pipx when the system Python is externally managed.
Both channels expose `qiongli` and `ql`. npm requires Node 18+; wheels require
Python 3.9+. Both package their executables without an install-time binary
download. Standalone GitHub archives require neither Node nor Python.

Supported targets are macOS Apple Silicon, Windows x64 and Linux x64
(glibc 2.35+). The release requires native builds and final combined-package
installation checks on all three systems, tied to one source commit. Public
downloads must match those qualified bytes. npm `latest` remains on 1.x.

For MCP, use the installed executable with
`mcp serve --profile full --transport stdio` (or `--profile lite`). The Host owns
models and credentials. Never replace existing research data during installation.

The public marketplace Plugin requires Node 18+ and npm access on first MCP
startup. It exposes the 14-tool Lite profile. The CLI also supports the 32-tool
Full profile; local Plugin export/Host configuration remains the explicit path
to that profile. Identical research resources and runtime version do not mean
that these two MCP profiles expose the same tools.

## Limits and rollback

Cargo source packaging exists, but public Cargo installation is deferred until
registry credentials and the publication/install gates pass. Intel macOS, Linux
ARM and Windows ARM-native are not advertised. Managed activation, signed
self-update, automatic migration and complete 1.x replacement remain separately
gated. This prerelease does not claim new live model quality results.

Upgrade through the package manager or a fresh extraction directory. Preserve
research data/backups and the previous executable. For package rollback, select
`qiongli@2.0.0-alpha.7` on npm or `qiongli==2.0.0a7` on PyPI; binary rollback does
not reverse data migrations. Published tags and assets are immutable.
